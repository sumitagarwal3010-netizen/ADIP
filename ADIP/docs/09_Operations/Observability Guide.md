# ADIP Observability Guide

How ADIP exposes metrics, structured logs, tracing seams, audit logs, and LLM
telemetry — and how to wire dashboards and alerting on top of them.

> Implemented today in a dependency-free, self-hosted-friendly way. Every
> primitive is a seam for a full backend (Prometheus / OpenTelemetry / ELK)
> without changing application code.

---

## 1. Metrics

**Endpoint:** `GET /metrics` → in-process request counters and latency.

```json
{
  "total_requests": 1200,
  "total_errors": 3,
  "avg_latency_ms": 42.7,
  "top_paths": [{ "path": "/api/v1/sdlc/...", "count": 380 }]
}
```

- Source: `backend/app/core/metrics.py` (`Metrics`), fed by
  `RequestContextMiddleware` in `backend/app/core/middleware.py`.
- **LLM runtime metrics:** `GET /api/v1/llm/runtime` →
  concurrency in-flight, circuit-breaker state, prompt/response cache hit rates,
  cumulative prompt/completion tokens and estimated cost.

### Prometheus adoption (future)

Replace the `Metrics.snapshot()` body with `prometheus_client` counters /
histograms and expose them at `/metrics` in Prometheus text format. No caller
changes required.

## 2. Structured logging

- Source: `backend/app/core/logging.py` (`get_logger`).
- Every request carries a **request id / correlation id** via
  `RequestContextMiddleware`; include it in log lines and error responses.
- Recommended production config: JSON log formatter, ship to ELK / Loki /
  CloudWatch. Set level via `LOG_LEVEL` env var.

**Log categories**
| Category | Logger name | Example |
|---|---|---|
| Request logs | `app.main` / middleware | method, path, status, latency, request_id |
| LLM logs | `app.llm.*` | provider, model, fallback used, tokens, breaker trips |
| Audit logs | `app.services.audit_trail` | who/what/when for prompts, artifacts, approvals |
| Datasets/perf | `enterprise-datasets`, perf harness | batch counts, throughput |

---

## 3. Tracing (seam)

ADIP is structured for distributed tracing without being coupled to a vendor:

- The request-context middleware is the natural place to start a root span.
- Service methods (`PromptExecutionEngine.execute`, `ArtifactGenerator.generate`,
  `LLMRuntime.complete`) are coarse spans.
- **To enable OpenTelemetry:** add `opentelemetry-instrumentation-fastapi` and
  `opentelemetry-instrumentation-sqlalchemy`, configure an OTLP exporter, and
  wrap the three service methods above with spans. Correlation id already flows
  through the middleware.

---

## 4. Audit logs

- Source: `backend/app/services/audit_trail.py` + the `ActivityLog` model.
- Recorded for prompt execution, artifact generation, and (via Prompt Studio)
  approval/publish transitions.
- Query historically through the activity-log CRUD/analytics endpoints.

## 5. Health & readiness

| Probe | Endpoint | Use |
|---|---|---|
| Liveness | `GET /health` | container alive |
| API health | `GET /api/v1/health` | app + DB reachable |
| LLM health | `GET /api/v1/llm/health` | active provider reachable / mock mode |
| Runtime | `GET /api/v1/llm/runtime` | concurrency, breaker, caches, cost |

## 6. Dashboards (recommended layout)

**Platform health dashboard**
- Requests/min, error rate, p50/p95/p99 latency (from `/metrics` + perf reports).
- Top 10 endpoints by volume.
- DB connection health.

**AI performance dashboard**
- Prompt/token throughput, average quality score, reviewer score trend.
- LLM cache hit rate, circuit-breaker state, fallback frequency.
- Cumulative token cost (from `/api/v1/llm/runtime`).

**Business dashboard**
- Artifacts generated by type/domain, quality band distribution.
- Prompt approval funnel (Draft → In Review → Approved → Published).

> Generate baseline numbers with `python -m app.perf.harness`; the report lands
> in `docs/examples/performance/`.

## 7. Alerting hooks

Wire alerts on these signals:

| Signal | Condition | Action |
|---|---|---|
| Error rate | `total_errors / total_requests > 2%` over 5m | page on-call |
| Latency | p95 > SLO (e.g. 800ms) over 5m | investigate |
| Circuit breaker | state `open` | LLM provider incident runbook |
| Cache hit rate | prompt/response hit rate < 20% sustained | review caching / prompts |
| Token cost | daily estimated cost > budget | throttle / switch to local model |

**Implementation seam:** add a small alert evaluator that reads `/metrics` and
`/api/v1/llm/runtime` on a schedule and posts to Slack/PagerDuty/webhook. No
core changes needed.
